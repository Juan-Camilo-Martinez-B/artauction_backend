# WebSocket v1

Sala en vivo de una subasta. El cliente calcula el countdown con `serverTime` y su reloj local. El servidor es la única fuente del cierre.

Conexión Socket.IO. El access token va en `handshake.auth.token`. Cada sala es `auction:{auctionId}`.

## Cliente → servidor

| Evento | Cuerpo | Efecto |
| --- | --- | --- |
| `auction:join` | `auctionId` | Entra en la sala y recibe `serverTime`. |
| `bid:place` | `{ auctionId, amount, idempotencyKey }` | Intenta la puja con el mismo candado que HTTP. |

## Servidor → cliente

| Evento | Cuerpo |
| --- | --- |
| `serverTime` | `{ version: 1, serverTime }` |
| `bid:accepted` | `{ version: 1, auctionId, bidId, bidderId, amount, endsAt, extended, serverTime }` |
| `bid:rejected` | `{ version: 1, auctionId, message, serverTime }` |
| `auction:closed` | `{ version: 1, auctionId, lotId, winnerId, amount, serverTime }` |

`extended: true` significa que la puja cayó en los últimos 30 segundos y `endsAt` avanzó otros 30. Una puja repetida con la misma `idempotencyKey` no vuelve a emitir `bid:accepted`.

HTTP equivalente: `POST /auctions/{id}/bids` y `GET /auctions/{id}`, que también devuelve `serverTime`. El contrato OpenAPI sale de `/docs`.
